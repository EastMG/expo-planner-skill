# expo-planner-skill

给线下展会做观展规划的 Agent Skill：**游戏嘉年华 / 漫展 / FES / 音乐会 / 签售会**。

它只回答四件事：**几点必须出门、几点必须离场、哪个馆有什么、谁在哪天。**

---

## 输出什么

固定三段，每段有硬性规格：

### 一、通勤时间表
逐时刻表（时间在第一列）+ 单独一段「末班卡点」+ 公共交通与打车两个方案，各自带时长、价格、到家时间。

### 二、场馆 / 展馆 / 展位
「馆 × 功能 × 内容」三列表、完整摊位表（按分区）、重点展位逐个说明、官方展区规则速查。

### 三、嘉宾 / coser / UP 主 行程
「日期 × 时段」二维表、签赠规则（人数/资格/进场时间）、个人自述行程表、每段一句结论。

**不做**：场内逐小时动线。精确到 15 分钟的逛展路线在现场必然崩，不给。

---

## 为什么这样切

展会规划的真实痛点不是"不知道逛什么"，而是：

- 快速票和普通票入场差 1 小时，直接决定限定款能不能买到；
- 单日票只有 1 次入场，停止入场又早于闭馆，中午出去吃饭就回不来；
- 演出 22:00 结束，末班车 22:44，换乘那一程可能只剩十几分钟；
- 官方日程只写「上午 / 中午 / 下午」，任何精确钟点都是猜的。

这些都是**约束**，不是建议。skill 的写法约定就是围绕"把约束写死、把猜测标明"。

## 安装

把整个目录拷进你的 agent 的 skills 目录即可，无需依赖：

```bash
# DeepSeek Harness
~/.dsh/skills/expo-planner-skill/

# 通用 Agent Skills 目录
~/.agents/skills/expo-planner-skill/
```

拷完后 agent 会在遇到「展会 / 漫展 / FES / 嘉年华 / 通勤 / 末班车 / 嘉宾行程」这类请求时自动加载。

## 用法

> 帮我按 expo-planner-skill 规划 <展会名>，票是 <日期/票种>，从 <住址> 出发

或者直接描述场景：「周六周日去 XX 展会，帮我排通勤，再把场馆和嘉宾行程总结一下」。

skill 会先问 4 件事（票种、出发地、最想看谁、签赠/预购抢到没），然后按三段输出。

## 设计约定

1. 信息优先级：官方公告 > 票务页细则 > 参展商/摊主自述 > 社区攻略 > 二手转述。
2. 官方没给的钟点不许编，要写必须标「（估算）」。
3. 票务硬规则单独成条：开展 / 停止入场 / 闭馆 / 入场次数 / 实名 / 限购。
4. 每条结论带来源；个人行程标「自述」+ 抓取日期。
5. 卡点写「必须」，不写「建议早点走」。
6. 用户没抢到的福利，直说拿不到，不用排程粉饰。

---

## 适用边界

- **适合**：一次性的线下活动前规划，尤其是需要通勤、有分日嘉宾、有实体展位的活动。
- **不适合**：旅行行程规划（那是另一类问题）、活动本身的攻略考据、票务代抢。
